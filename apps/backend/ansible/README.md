# DraftDock Backend — Deployment Guide

Deploys `mistaholmes/draftdock-be-mar-21:latest` on an AWS EC2 `t3.small`
(10 GiB gp3) instance. Nginx is installed natively (not in Docker) and
reverse-proxies two virtual hosts:

| Virtual host | Nginx port | Container port | Protocol |
|---|---|---|---|
| `draftdock-be.abhasbehera.in` | 80 | 3000 | HTTP REST |
| `ws-draftdock-be.abhasbehera.in` | 80 | 3001 | WebSocket |

---

## How the playbook works

`deploy.yml` is a **two-stage** playbook. Both stages run with a single command,
or you can run them independently.

```
Stage 1 [provision]  — localhost
  └─ creates .key/draftdock.pem (SSH key pair)
  └─ terraform init + apply  →  EC2 instance + Security Group + Key Pair
  └─ auto-generates inventory.ini with the new IP
  └─ registers host in memory for immediate Stage 2

Stage 2 [deploy]     — EC2 instance (Ubuntu 24.04)
  └─ apt install nginx + Docker CE
  └─ docker pull mistaholmes/draftdock-be-mar-21:latest
  └─ docker run  (ports 3000 + 3001, all env vars hardcoded)
  └─ nginx config  (HTTP → 3000, WebSocket → 3001)
  └─ health checks on both ports
```

## Prerequisites

| Tool | Version |
|---|---|
| Terraform | ≥ 1.5 |
| Ansible | ≥ 2.14 |
| AWS CLI | configured via `aws configure` |

No extra Ansible collections are needed — Docker is managed via plain shell commands.

## Commands

### Full deploy (provision + deploy)

```bash
cd apps/backend/ansible
ansible-playbook deploy.yml
```

This will:
1. Generate `.key/draftdock.pem` (if it doesn't exist)
2. Run `terraform apply` to create the EC2 instance
3. SSH in and deploy the container + nginx

At the end, the playbook prints the instance IP and SSH command.

---

### Skip Terraform — deploy only (instance already exists)

Use this when the EC2 instance is already running and you just want to
re-deploy the container or update config:

```bash
ansible-playbook deploy.yml -e "terraform_skip=true"
```

Stage 1 is skipped entirely. The existing `inventory.ini` (written by
Terraform on the first run) is used to find the instance.

---

### Run a single stage

```bash
# Provision only (create infra, no app deploy):
ansible-playbook deploy.yml --tags provision

# Deploy only (same as terraform_skip=true):
ansible-playbook deploy.yml --tags deploy -i inventory.ini

# DNS-Update only (update dns on cloudflare):
ansible-playbook deploy.yml -t dns
```

## Get the instance IP

```bash
# After terraform apply:
cd apps/backend/ansible/terraform
terraform output instance_public_ip

# Or from anywhere in the project:
terraform -chdir=apps/backend/ansible/terraform output instance_public_ip
```

The IP is also printed at the end of the full `ansible-playbook deploy.yml` run.

---

## SSH into the instance

```bash
ssh -i apps/backend/ansible/.key/draftdock.pem ubuntu@<IP>
```

Useful commands once inside:

```bash
# Check running containers
sudo docker ps

# Follow container logs
sudo docker logs draftdock-be -f

# Restart container
sudo docker restart draftdock-be

# Nginx logs
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log
```

---

## Re-deploy after image update

```bash
# Pull new image and restart (deploy stage only):
ansible-playbook deploy.yml -e "terraform_skip=true"
```

## Tear down

```bash
cd apps/backend/ansible/terraform
terraform destroy -auto-approve
```

```
    ├── main.tf                      # EC2 t3.small, 10 GiB gp3, SG, key pair
    ├── variables.tf
    └── outputs.tf                   # prints IP, DNS, SSH command
```

  block (skipped when terraform_skip=true):

## Cloudflare DNS integration

This playbook can automatically create/update A records in Cloudflare for your
two domains:

- `draftdock-be.abhasbehera.in`
- `ws-draftdock-be.abhasbehera.in`

Required information (hardcoded into `deploy.yml` as requested):

- `cloudflare_api_token` — a Cloudflare API Token with the `Zone:DNS:Edit`
  permission for the target zone. This is the recommended scoped token.
- `cloudflare_zone_id` — the Zone ID for your Cloudflare domain (found in
  the Cloudflare dashboard under the domain Overview page).

How the playbook uses them

- Stage 1 writes the instance public IP to `./.last_instance_ip` after
  provisioning. The DNS stage reads that file and updates (or creates) the
  A records pointing at the new IP.
- If you skip terraform (use `-e "terraform_skip=true"`), provide the IP
  manually when running the DNS stage with `-e dns_ip=<IP>`.

Security note

The playbook currently contains placeholder values for `cloudflare_api_token`
and `cloudflare_zone_id` in `deploy.yml`. Replace the placeholders with your
real token and zone ID before running the DNS stage, or provide them via
extra-vars.

Example: run DNS update only (using an explicit IP):

```bash
cd apps/backend/ansible
ansible-playbook deploy.yml -t dns -e "dns_ip=1.2.3.4" -e "cloudflare_api_token=REPLACE" -e "cloudflare_zone_id=REPLACE"
```

Alternatively run the full playbook (provision + dns + deploy):

```bash
ansible-playbook deploy.yml
```
